# Manager Protocol

> **Generated by project-context.** Upgrade framework files through
> `project-context upgrade`; plans and tasks are living Markdown, while JSONL
> history is append-only.

Read the target repository's root `AGENTS.md` before working. This manager adds
durable planning state; it does not replace repository conventions.

## One workflow

```text
/pc-plan start <goal>
/pc-plan continue [PLAN-NNN]
/pc-plan status [PLAN-NNN]
/pc-plan run [PLAN-NNN]
```

`pc-plan` is the only generated workflow skill. Context, task registration,
readiness, graph, status, review, archive, and UUID operations are internal
mechanics, not user-facing skills.

## Durable state and ownership

`PLAN-NNN → TASK-NNN` is the only artifact hierarchy. Plan Markdown and
append-only task JSONL are the recovery state. Only one plan may be
non-terminal; `continue` and `run` resume at its first incomplete persisted
gate. Explicit acceptance sets the plan to `committed` and records
`User accepted: yes` in its Planning Gate.

The root coordinator owns discovery, the compact plan, user questions,
acceptance, task decomposition, integration, and manager-state writes. Every
narrow task packet declares exact write paths and symbols, boundaries, tests,
verification, proof obligations, and `needs_planning` conditions. Workers
change only their packet, never ask the user, commit, mutate manager state, or
expand scope.

Run at most three dependency-ready writers with disjoint exact write sets. One
challenger reviews each completed packet. A planning gap returns
`needs_planning` to the coordinator, which revises the smallest in-scope
boundary from repository evidence and accepted decisions. Commits, combined
checks, and manager-state transitions stay serial.

## Canonical skills and memory

The manager keeps only `.agents/skills/pc-plan/SKILL.md`. Shared skills are
canonical references under `/Users/brian/.agents/skills/<skill-name>/SKILL.md`;
they are selected from `data/skills.json` and are never copied into the
manager. A missing selected skill blocks packet generation before dispatch.

MemoryLake supplements accepted decisions and verified outcomes only. Read
`data/identity.json` first and scope every MemoryLake operation to its exact
`memoryLake.projectId`; never search an unfiltered workspace. The root agent
alone writes durable memory. Local plan and task state remain authoritative.

The coordinator's persisted lifecycle is in `workflows/pc-plan.md`.
