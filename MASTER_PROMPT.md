## What you are building

project-context is an npm package that scaffolds a `.ai/` directory
into any project. The `.ai/` directory is a project management system
for AI agents — it gives Devin, Cursor, Claude Code, and other agents
the context they need to understand a project's specs, plans, tasks,
workflows, state, and decisions.

The tool is invoked as:

```
npx project-context init [--workspace .ai] [--target .]
npx project-context inspect [--workspace .ai]
npx project-context graph [--workspace .ai]
npx project-context overview [--workspace .ai]
```

- `init` — scaffold the `.ai/` directory with workflows, templates,
  AGENTS.md, and empty context directories. Optionally run discovery
  to populate identity, architecture, and graph nodes.
- `inspect` — read the existing `.ai/` directory and report state
  (which specs/plans/tasks exist, their status, progress).
- `graph` — build graph nodes and edges from the project's source
  files and `.ai/` context files.
- `overview` — generate a CSV overview of all specs, plans, and tasks
  from their Status sections. Opens in Excel.

### Workflows — the process files to generate

The workflows in `/Users/brian/code/trust/.ai-trust/context/workflows/`
are the canonical versions. Copy them into `.ai/context/workflows/`
during init. Read each one to understand the pattern:

**spec-creation.md** — Writer-critic-blind pattern for specs:
- Writer loads `adhd` skill for divergent ideation
- Critic reviews with context (1-2 sentence summary)
- Blind reviewer reviews against AGENTS.md + architecture doc only
- Max 3 rounds, then escalate to user
- Produces a spec file (what/why, not how)

**plan-creation.md** — Same pattern for plans:
- Writer loads `adhd` skill
- Plan calls out actual files, skills (from algorithms.json), deps
- Critic checks spec coverage, approach, skill alignment
- Blind reviewer checks algorithm-to-skill matrix, test vectors

**task-creation.md** — Same pattern for tasks:
- Writer loads primary skill + `adhd` skill
- Context packets defined for each role (writer, critic, blind)
- Critic checks plan alignment, technical accuracy
- Blind reviewer checks standards, format, rule compliance

**task-implementation.md** — Assembly line for code:
- Primary implements (primary skill loaded)
- Secondary reviews + fixes (secondary skill, write access)
- Code reviewer checks against rules (go-code-review skill, background)
- Testing agent writes full test suite (golang-testing skill, background)
- No adhd — design is settled by this point

**code-review.md** — PR review only (dev → master):
- Reviews cumulative diff, not individual tasks
- Loads go-code-review skill
- Runs govulncheck, checks branch protection

### AGENTS.md — the protocol file

The `.ai/AGENTS.md` file is the entry point for any AI agent working
on the project. Read `/Users/brian/code/trust/.ai-trust/AGENTS.md`
for the canonical version. It must contain:

1. **Session start** checklist (read identity, load skills, consult
   architecture, inspect state, inspect specs/plans, follow workflows)
2. **Workflows table** listing all 5 workflows with filenames and when
   to use them
3. **Lifecycle diagram** showing the flow:
   ```
   SPEC → spec-creation → commit
   PLAN → plan-creation → commit
   TASK → task-creation → commit
   TASK → task-implementation → done
   All tasks done → PR dev → master → code-review → merge
   ```
4. **Where skills attach** — which skills load at which workflow stage
5. **Building a plan** — how to consult algorithms.json, confirm
   skills installed, cite standards
6. **During implementation** — the 8-step pipeline

The AGENTS.md should reference a root `AGENTS.md` (in the project
root, not `.ai/`) for project-specific conventions. The root
AGENTS.md is NOT generated by this tool — it's project-specific.

### overview.csv — the spreadsheet view

Generated by the `overview` command. Reads all spec, plan, and task
files, parses their `## Status` sections, and emits CSV rows:

```csv
Type,ID,Title,Status,Progress,Dependencies,Notes
SPEC,SPEC-001,trust — Cryptographic Trust Core,committed,0% (0/3 plans done),none,...
PLAN,PLAN-001,Primitive Wrappers,in_progress,69% (9/13 tasks done),SPEC-001,...
TASK,TASK-001,SHA-256 wrapper,done,—,TASK-005,...
```

Columns: Type, ID, Title, Status, Progress, Dependencies, Notes.
The CSV is generated, not hand-maintained. The markdown files are
the source of truth.

## Discovery (the `init` command with `--discover` flag)

When `init` is run with `--discover`, the tool inspects the target
project and populates:

1. **`context/identity/project.md`** — project name, description,
   language, key directories, module structure. Infer from:
   - `package.json`, `go.mod`, `Cargo.toml`, `pyproject.toml`, etc.
   - Git remote URL (for project name)
   - Directory layout (top-level directories and their purpose)

2. **`graph/nodes/`** — JSON files for each top-level directory and
   key source files. Each node has:
   ```json
   {
     "id": "trust",
     "type": "module",
     "path": "trust/",
     "language": "go",
     "imports": ["crypto/sha256", "crypto/aes"],
     "exports": []
   }
   ```

3. **`graph/edges/`** — JSON files describing relationships between
   nodes (module dependencies, spec→plan→task links):
   ```json
   {
     "from": "trust",
     "to": "auth",
     "type": "dependency"
   }
   ```

## Constraints

- **No Python.** The existing Python scripts should be deleted or
  archived. The tool is Node only.
- **No bash for core logic.** Bash is fine for a Makefile or CI
  script, not for the tool itself.
- **Templates are the source of truth.** The templates in
  `src/templates/` are what get copied into target projects. They
  must match the trust reference exactly (Status, Progress, lifecycle).
- **Workflows are the source of truth.** The workflow files in
  `src/workflows/` must match the trust reference exactly.
- **The tool does not carry project-specific content.** It carries
  the framework (workflows, templates, AGENTS.md protocol). Target
  projects create their own specs, plans, and tasks.
- **overview.csv is generated, not maintained.** The `overview`
  command reads markdown files and emits CSV. The markdown files are
  the source of truth.
